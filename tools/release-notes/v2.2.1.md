Ponko is an offline-capable AI app for Android: chat (image, file and document input) +
drawing + tagging, each of which can be served over its own OpenAI-compatible API.
All inference runs on-device: apart from the optional in-app LoRA download, no feature
needs the network. No telemetry; your data stays on your phone.
See the [README](https://github.com/visitor257/Ponko#readme).

**This is a stable patch release.** It upgrades 2.2.0 in place - same package
(`com.litertchat.app`), same signing key, so imported models and settings are kept.

## What changed since 2.2.0

### Video generation (first version)

sd.cpp has had a video pipeline for a while (`generate_video()`, `sd_vid_gen_params_t`);
the app had none. In 2.2.0 the video-model import entry was removed precisely because
importing a 10-20 GB checkpoint ended in a generic "generation failed". Both halves are
back, and now they connect.

- **Import** works again: Draw -> Models -> Import -> "Video (Wan / LTX-V ...)", single
  file or multi-file. Slots are diffusion (required) + vae (required), with clip_vision /
  t5xxl / llm / audio_vae optional.
- **Generate** in **Ponko-EX -> JSON plugins -> Video**: pick the model set, load it
  (a video model takes minutes), set prompt / frames / fps / size / steps / cfg / sampler /
  scheduler / seed, press generate.
- Each frame is written as a PNG into the app-private `draw/videos/<timestamp>/`; the
  result tab plays them back at the fps you chose, with a scrubber. A live preview updates
  every sampling step while it runs.
- Progress reports the loading percentage, then `step N/M`, elapsed time and an estimate.
  Stop cancels at the next sampling step. The model can be loaded and unloaded separately
  from generating, so trying a second prompt does not pay the load cost again.

**What this does not do yet** - stated plainly so nobody downloads 20 GB on a wrong
assumption:

- **Text-to-video only.** `init_image` / `end_image` / reference videos are real fields in
  sd.cpp, but there is no control in the app to pick an image for them yet.
- **No mp4.** 2.2.1 writes a PNG sequence; there is no encoder in the app. Playback and
  frames on disk are what you get.
- **No audio track.** Models that emit audio (H3 / Wan S2V) have their samples dropped.
- **One job at a time**, and leaving the page frees the model context - video contexts map
  tens of GB and keeping one alive next to an image model is how an 8 GB phone dies.
- **Model support is whatever sd.cpp recognises** at its 2026-11-13 snapshot: HunyuanVideo
  1.0, Wan 2.x, LTX-V, MiniMax-H3 and friends. **HunyuanVideo 1.5** uses a different DiT
  tensor layout than the loader probes for, so it is not verified - if it fails to load,
  the log now carries sd.cpp's own reason.

### JSON plugins

A second kind of plugin, next to Ponko-EX (independent APK + AIDL): **one `.json` file**
that describes a page and which host action each button calls. No code, no APK, no process,
no signing.

- Lives in `filesDir/json-plugins/`; **Import JSON** in the Ponko-EX tab copies one in from
  anywhere the system file picker can reach.
- The video page above *is* one of these files - it ships in the APK and is unpacked on
  first run, so the feature has a working example instead of an empty list. Delete it and
  it stays deleted.
- Controls: text, sections, switch, slider, choices, text / textarea, buttons, progress,
  status row, log box, image, tab pages, rows / groups, dividers - plus two host-provided
  ones: a **model-set picker** and a **frame player**.
- Actions: `host.video`, `host.cancel`, `host.video.load`, `host.video.unload`, and for
  Ponko-EX plugins `plugin.set` / `plugin.invoke` / `plugin.engine` / `plugin.synthesize`.
  The only variable is `$ui.<key>` (the value of a control). One action = one call; the
  file never describes a data flow, and the host never writes back to it - control values
  are stored per plugin id in preferences.
- Unknown control types and unknown host actions are reported on the page instead of
  failing silently, so a typo in a file is visible.

### Fixed

- A video model left selected on the drawing page no longer runs into a generic failure:
  pressing generate says which page can actually produce frames.

## Please read before reporting

- **What was run on a device** (iQOO 3 / Snapdragon 865, Android 13, CPU path): installed
  over 2.2.0 in place - imported models and settings kept; the new prediction selector reads
  back as expected (`EDM v` -> `sd.cpp running in v-prediction EDM mode`, `Auto` -> eps);
  both load-time controls are greyed out while a model is loaded; a 256x256 / 20-step CPU
  image finished in 220 s. Video was not run - no video checkpoint has been through this
  device yet, so how fast a video model runs, or whether a specific checkpoint loads, is
  still unknown.
- If a video model fails to load, the path to send is the JSON page's log box (it carries
  sd.cpp's WARN/ERROR lines) or `logs/draw.log`.
- Frames are stored under the app's private directory. Copying them out is currently a
  manual file-manager job; an export action is on the list.

## 中文说明

**这是稳定版的补丁版本**：直接覆盖 2.2.0 安装（同包名、同签名），已导入的模型和设置都保留。

### 相对 2.2.0 改了什么

#### 视频生成（第一版）

sd.cpp 早就有一整套视频管道（`generate_video()`、`sd_vid_gen_params_t`），但 App 一行都没接。
2.2.0 把「视频模型」的导入入口摘掉，正是因为导进来之后点生成只会得到一句「生成失败」。
这次两半都补上，并且接起来了。

- **导入**加回来：「绘图 → 模型 → 导入 → 视频（Wan / LTX-V 等）」，单文件、多文件都行。
  槽位是 diffusion（必填）+ vae（必填），clip_vision / t5xxl / llm / audio_vae 可选
- **出片**在 **Ponko-EX → JSON 插件 → 视频生成**：选模型集 → 加载（视频模型要几分钟）→
  填提示词 / 帧数 / 帧率 / 尺寸 / 步数 / 文本引导 / 采样器 / 调度器 / 种子 → 生成
- 每帧写成一张 PNG，落在应用私有目录 `draw/videos/<时间戳>/`；结果页按你设的帧率轮播，
  带拖动条。采样过程中还有一张实时预览，每步更新
- 进度分两段：先是加载百分比，然后是「第 N/M 步 · 已 X 秒 · 剩余约 Y 秒」；
  「停止」会在下一个采样步之前退出；模型可以**单独加载 / 卸载**，换提示词不用重新等一遍

**这一版还做不到的**（写清楚，免得有人按错误的预期去下 20 GB）：

- **只有文生视频**。`init_image` / `end_image` / 参考视频在 sd.cpp 里都是真字段，
  但 App 里还没有"选一张图"的控件
- **不导出 mp4**。2.2.1 产出的是 PNG 序列，App 里没有编码器
- **不保留音轨**。会出音频的模型（H3 / Wan S2V）那部分直接丢掉
- **同时只能跑一个任务**；离开页面会释放模型 context —— 视频模型动辄占十几 GB 映射，
  和绘图模型同时活着，8 GB 的手机会直接崩
- **能跑哪些模型取决于 sd.cpp**（2026-11-13 快照）认得出什么：HunyuanVideo 1.0、Wan 2.x、
  LTX-V、MiniMax-H3 等。**HunyuanVideo 1.5** 的 DiT 张量布局和加载器找的那套不同，
  没有验证过 —— 要是加载失败，日志里会有 sd.cpp 自己的原因

#### JSON 插件

和 Ponko-EX（独立 APK + AIDL）并列的第二种插件：**一个 `.json` 文件**，写清页面怎么排、
每个按钮调哪个宿主动作。没有代码、没有 APK、没有进程、不用签名。

- 放在 `filesDir/json-plugins/`；插件页的「导入 JSON」可以从系统文件选择器能到的地方选一份
- 上面那个**视频页本身就是一份 JSON 插件** —— 它随包带着、首次启动解包到目录里，
  所以这个功能打开就有个能用的例子，而不是一片空白。删掉之后不会再自动长回来
- 控件：文本、分组、开关、滑块、单选、单行 / 多行输入、按钮、进度条、状态行、日志框、
  图片、标签页、行 / 分组、分隔线；另外两种只有宿主提供的：**模型集选择**和**帧播放器**
- 动作：`host.video`、`host.cancel`、`host.video.load`、`host.video.unload`；
  对 Ponko-EX 插件还有 `plugin.set` / `plugin.invoke` / `plugin.engine` / `plugin.synthesize`。
  唯一的变量是 `$ui.<key>`（取某个控件的值）。**一条动作 = 一个调用**，
  文件不描述数据流，宿主也从不回写文件 —— 控件值按插件 id 存进偏好
- 认不出的控件类型、宿主没有的动作，都会直接显示在页面上，而不是静默失败 ——
  文件写错了要能一眼看出来

#### 修复

- 绘图页选中的是视频模型时，不再一路跑到「生成失败」：现在会直接告诉你去哪一页出片。

### 请注意

- **在真机上跑过的部分**（iQOO 3 / 骁龙 865、Android 13、CPU）：覆盖安装 2.2.0 后模型和
  设置都在；新的预测类型下拉选「EDM v」日志里是 `sd.cpp running in v-prediction EDM mode`、
  选「自动」回到 eps；模型加载后两个加载期控件都置灰；256×256 / 20 步 / CPU 出图 220 秒
- **没跑过的部分**：视频生成和 JSON 插件页只过了编译，这台机器上还没有视频权重。
  视频模型跑多快、某个具体权重能不能加载，仍要实测才知道
- 加载失败要把 JSON 页的日志框（里面有 sd.cpp 的 WARN/ERROR）或 `logs/draw.log` 发出来
- 帧存在应用私有目录里，导出去目前得手动拿文件管理器拷；「导出」动作在待办里
