Ponko is an offline-capable AI app for Android: chat (image, file and document input) +
drawing + tagging, each of which can be served over its own OpenAI-compatible API.
All inference runs on-device: apart from the optional in-app LoRA download, no feature
needs the network. No telemetry; your data stays on your phone.
See the [README](https://github.com/visitor257/Ponko#readme).

## What's new in v2.0.4

A system prompt for chat, and enough diagnostics to answer "is my LoRA actually doing
anything".

### System prompt

- A gear button on the chat page opens a bottom sheet where you write the persona or rules
  for the conversation. It is stored **per conversation**, not globally - each chat keeps
  its own, and the sheet names which conversation you are editing so it cannot be mistaken
  for an app-wide setting
- Saving applies immediately: the conversation is rebuilt so the new prompt takes effect
  without starting over, and your history is carried across
- Clear is done by saving an empty field - the separate Clear button is gone, since it took
  two taps to do what Save does with one
- **Fixed**: a prompt edited mid-conversation had no effect. The prompt was being appended
  to the conversation transcript instead of being set as the system instruction, so the
  model read it as something said earlier in the chat rather than as standing instructions.
  Against four turns of an established role it always lost. It now goes where the SDK
  actually reads it
- Version 2.0.3 -> 2.0.4 (versionCode 23 -> 24)

### Diagnostics for drawing

The drawing engine reports every decision it makes about a LoRA through a log callback that
this app had never registered, so all of it was discarded - not to the log file and not to
logcat. The messages lost were the ones that answer why a LoRA appeared to do nothing:

```
skip incompatible LoRA tensor |x|: model shape = [...], LoRA shape = [...]
model manager skipping direct lora application to row-split tensors
required lora load failed: ...
```

- Those are now captured and written into the DRAW log as a `-- sd.cpp warnings --` section,
  which travels with the diagnostics report. Warnings and errors only, deduplicated, capped
  at 40 lines - a mismatched LoRA can emit the same skip notice for each of its hundreds of
  tensors, and that report is what gets attached to a bug
- INFO lines that mention LoRA are passed through as well, because the success path is
  otherwise silent too: the applied-tensor count is logged at INFO when everything matched,
  and escalates to WARN only when something did not. Without it, "all tensors applied" and
  "the statistic never ran" look identical
- Image-to-image had no `finally` block, so its warnings were lost on both success and
  failure. It has one now
- Sampler/CFG/resolution behaviour is unchanged. This is visibility, not a fix

## 中文说明

Ponko 是一个可离线运行的 Android AI 应用：对话（支持图片、文件、文档输入）+ 绘图 + 打标，
三者都能各自开一个 OpenAI 兼容 API。所有推理都在设备本地完成——除了可选的 App 内 LoRA
下载，任何功能都不需要联网。无遥测，数据留在你手机上。

### v2.0.4 更新内容

一个对话用的系统提示词，以及足以回答「我的 LoRA 到底有没有起作用」的诊断信息。

#### 系统提示词

- 对话页右上角的齿轮按钮打开一个底部抽屉，可以在里面写这个对话的人设或规则。
  **按对话各存一份**，不是全局设置——每个对话互不影响，抽屉里会写明你在改哪个对话，
  避免被当成整个 App 的设置
- 保存立即生效：会重建会话，新提示词不用重新开对话就起作用，历史记录照常保留
- 「清空」改成保存一个空输入框——原来那个独立按钮要两下才能做到保存一下能做的事，已去掉
- **修复**：对话中途改提示词不生效。提示词当时被塞进了对话历史，而不是设成系统指令，
  模型把它当成「聊天里之前说过的一句话」，而不是会覆盖行为的规定。对着四轮已经成立的
  角色扮演，这一句永远输。现在它被放到 SDK 真正读取的位置
- 版本 2.0.3 → 2.0.4（versionCode 23 → 24）

#### 绘图诊断

绘图引擎对 LoRA 的每一个判断都通过一个日志回调发出，而这个 App 从来没注册过那个回调，
于是全部被丢弃——日志文件里没有，logcat 里也没有。丢掉的恰好是能回答「LoRA 为什么看起来
没起作用」的那几条：

```
skip incompatible LoRA tensor |x|: model shape = [...], LoRA shape = [...]
model manager skipping direct lora application to row-split tensors
required lora load failed: ...
```

- 现在会把它们收集起来，以 `-- sd.cpp warnings --` 一节写进绘图日志，跟着诊断报告一起走。
  只收警告和错误，去重，上限 40 条——一个不匹配的 LoRA 会为它几百个张量每个都报一次同样的
  跳过提示，而那份报告是要附进 bug 的
- 提到 LoRA 的 INFO 也一并放行，因为成功路径同样是静默的：全部匹配时，应用到的张量数是
  INFO 级别，只有出问题才升成 WARN。少了它，「全部应用」和「统计根本没跑」长得一模一样
- 图生图这条路径原本没有 `finally`，成功和失败都会丢掉警告。现在有了
- 采样器 / CFG / 分辨率的行为没有任何改动。这一版是让信息可见，不是修复
