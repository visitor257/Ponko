Ponko is an offline-capable AI app for Android: chat (image, file and document input) +
drawing + tagging, each of which can be served over its own OpenAI-compatible API.
All inference runs on-device: apart from the optional in-app LoRA download, no feature
needs the network. No telemetry; your data stays on your phone.
See the [README](https://github.com/visitor257/Ponko#readme).

**This is a beta build.** It installs alongside the stable app (package
`com.litertchat.app.beta`).

## What changed since 2.1.0-beta.1

Only diagnostics. Nothing about drawing, chat or the reference-image path itself is
different - if beta.1 worked for you, beta.2 works the same way.

A beta.1 report from a Krea2 run could not answer the question it was collected for:
whether the reference images had reached the model at all. The two lines inside sd.cpp that
say so - `Using 'krea2_ostris_edit' preset for reference images` and `EDIT mode` - are both
`LOG_INFO`, and the filter only passed INFO lines mentioning LoRA. They were dropped, so a
run with reference images and a run without them produced indistinguishable reports.

- That filter now passes any INFO line containing `lora`, `preset`, `reference image` or
  `edit mode`. It stays a whitelist rather than passing everything, because a mismatched
  LoRA can emit hundreds of skip notices and the report is capped at 40 lines
- The app writes the reference-image count into the DRAW log itself -
  `refImages=1 800x600`, or `refImages=none` - next to the existing size, steps, cfg and
  LoRA lines. sd.cpp's wording is upstream's to change; a line the app writes is ours

The reason this is worth its own build: one Krea2 render at 512x512 with 8 steps took
**91.7 minutes** on the device that reported it. A test that ends without a definite answer
costs an hour and a half to repeat.

## Still true from beta.1

- The 2.0.4 features: per-conversation system prompt, its `systemInstruction` fix, and the
  drawing diagnostics that surface the engine's LoRA decisions
- PixArt Sigma / Alpha now loads from diffusers-exported files (use the **SDXL VAE**;
  Sigma keeps the 0.13025 scale factor and an SD1.5 VAE gives wrong colours)
- MOSS-Image now loads from the Comfy layout (Qwen3.5 text encoder + Flux2 VAE)
- Reference images: up to two, shown only when the loaded model takes them, which opens
  Krea2 style reference, FLUX Kontext, Qwen-Image-Edit, Fibo 2, Longcat and MageFlow

## Please read before reporting

**Still no real device test beyond Krea2 text-to-image.** That one passed: the model loads,
`(512 / 512) LoRA tensors have been applied`, and the output quality is good. The
reference-image path itself has not been exercised on a real model yet, which is exactly
what beta.2's logging is for.

## 中文说明

Ponko 是一个可离线运行的 Android AI 应用：对话（支持图片、文件、文档输入）+ 绘图 + 打标，
三者都能各自开一个 OpenAI 兼容 API。所有推理都在设备本地完成——除了可选的 App 内 LoRA
下载，任何功能都不需要联网。无遥测，数据留在你手机上。

**这是测试版。** 它与正式版并存（包名 `com.litertchat.app.beta`）。

### 相对 2.1.0-beta.1 改了什么

只有诊断。绘图、对话、参考图通路本身没有任何变化——beta.1 能用的，beta.2 一样用。

beta.1 那份 Krea2 诊断报告回答不了它本来该回答的问题：参考图到底有没有送到模型。sd.cpp
里说这件事的两行——`Using 'krea2_ostris_edit' preset for reference images` 和
`EDIT mode`——都是 `LOG_INFO`，而过滤器只放行提到 LoRA 的 INFO 行。它们被丢掉了，于是
「加了参考图」和「没加参考图」两次运行产出的报告完全无法区分。

- 过滤器现在放行任何含 `lora`、`preset`、`reference image` 或 `edit mode` 的 INFO 行。
  仍然用白名单而不是全放，因为一个不匹配的 LoRA 能吐出几百条跳过提示，而报告上限是 40 行
- App 自己把参考图数量写进 DRAW 日志——`refImages=1 800x600`，或者 `refImages=none`——
  就写在已有的尺寸、步数、cfg、LoRA 那几行旁边。sd.cpp 的措辞是上游的，App 自己写的行才是我们的

为什么值得单独出一版：在那台报告设备上，Krea2 一张 512×512、8 步的图花了 **91.7 分钟**。
一个得不出确定结论的测试，重做一次就是一个半小时。

### beta.1 里仍然有效的内容

- 2.0.4 的功能：按对话保存的系统提示词、它的 `systemInstruction` 修复、以及把引擎的
  LoRA 判断输出到日志的绘图诊断
- PixArt Sigma / Alpha 现在能加载 diffusers 导出的文件（**VAE 请用 SDXL 的**，Sigma 保持
  0.13025 缩放因子，用 SD1.5 的会偏色）
- MOSS-Image 现在能加载 Comfy 的布局（Qwen3.5 文本编码器 + Flux2 VAE）
- 参考图：最多两张，只在当前模型接受参考图时显示，由此解锁 Krea2 的 style reference、
  FLUX Kontext、Qwen-Image-Edit、Fibo 2、Longcat、MageFlow

### 报告问题前请看

**除了 Krea2 的文生图，仍然没有经过真机测试。** 那一次通过了：模型能加载、
`(512 / 512) LoRA tensors have been applied`、出图质量很好。参考图这条通路本身还没在
真实模型上跑过——beta.2 的日志改动就是为此。
