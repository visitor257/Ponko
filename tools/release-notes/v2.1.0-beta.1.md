Ponko is an offline-capable AI app for Android: chat (image, file and document input) +
drawing + tagging, each of which can be served over its own OpenAI-compatible API.
All inference runs on-device: apart from the optional in-app LoRA download, no feature
needs the network. No telemetry; your data stays on your phone.
See the [README](https://github.com/visitor257/Ponko#readme).

**This is a beta build.** It installs alongside the stable app (package
`com.litertchat.app.beta`), so the two do not overwrite each other and the stable one keeps
working exactly as before. It carries what 2.0.4 shipped, plus three things only this
branch has.

## What's in this build

### From 2.0.4

- **A system prompt for chat**, set per conversation from a gear button on the chat page.
  Saving applies it to the ongoing conversation instead of making you start over, and the
  transcript is carried across. Clearing is done by saving an empty field; the separate
  Clear button is gone
- **Fixed**: a prompt edited mid-conversation had no effect. It was being appended to the
  transcript rather than set as the system instruction, so a chat that started as "you are
  a cat" kept playing cat after being changed to "you are a dog"
- **Drawing diagnostics**: the engine reports every LoRA decision through a log callback
  this app had never registered, so all of it went nowhere. Those lines - including the
  applied-tensor count and the "skip incompatible LoRA tensor" notices - now reach the DRAW
  log and travel with the diagnostics report

### PixArt now loads

Reported in #3 as "never generated anything or fails to load", in every import mode.

sd.cpp already supported PixArt. The failure was naming, in two places at once. A
diffusers-exported transformer carries no prefix at all - the 603 tensors in
PixArt-Sigma-XL-2-256x256 read `pos_embed.proj.weight`,
`transformer_blocks.0.attn1.to_q.weight` - while every detection branch asked for
`model.diffusion_model.*`, so the file was classified as something else entirely. And the
PixArt name converter rewrites the diffusers names correctly but relies on a later generic
map to add the prefix, which only fires for `transformer.` / `unet.` /
`diffusion_model.` - bare names never match, so the rewritten keys reached the model without
it and every lookup missed.

Both are fixed, and PixArt has its own family now instead of hiding under "other", so the
import dialog asks for the three files it actually needs: diffusion model, T5-XXL, VAE.
It has no CLIP at all - `caption_channels` 4096 is T5-XXL's hidden size.

Use the **SDXL VAE**. Sigma's weights carry no `csize_embedder`, so it keeps the 0.13025
scale factor, and an SD1.5 VAE will give you wrong colours.

### MOSS-Image now loads

Same cause. Comfy publishes its diffusion model in `diffusion_models/` with bare names -
379 tensors reading `video_embedder.weight`, `layers.0.proj.ffn_down.weight` - and the
detection branch asked for a prefixed name that was not there. That is "Moss models won't
load".

MOSS needed no new name mapping: the Comfy keys already match the model's internal names
one for one, so only the prefix was missing. Needs the Qwen3.5 text encoder and the Flux2
VAE.

### Reference images

This is what #4 asked for, and it unblocks more than Krea2.

`ref_images` is not the same thing as the img2img starting image, and only the former is
what a style-reference LoRA wants: it goes to the DiT as its own tokens, more than one is
allowed, and the model decides how they are treated. The app had no reference-image concept
at all - not in the JNI, not in the UI - so a style-reference LoRA could load and do nothing.

- A reference card on the drawing page: up to two images, tap a thumbnail to remove it
- **Only shown when the loaded model takes reference images.** The capability is asked of
  sd.cpp rather than guessed from the family name, because FLUX only accepts them in its
  Kontext variants, and handing reference latents to a model that does not expect them is
  not harmless - it changes the graph the model was built around
- Switching to a model without support clears the picks rather than leaving them to be sent
  later by surprise

Beyond Krea2's `krea2_turbo_style_reference` LoRA, this also opens FLUX Kontext,
Qwen-Image-Edit, Fibo 2, Longcat and MageFlow, none of which were usable before.

## Please read before reporting

**None of this has been through a real device test.** The name conversions were verified
against the actual weight files - 603 tensors for PixArt, 379 for MOSS, every key mapped,
nothing left over, no collisions - but no image has been generated from either, and the
reference-image path has never run against a real model. If something fails, that is
expected and useful information, not a surprise.

## 中文说明

Ponko 是一个可离线运行的 Android AI 应用：对话（支持图片、文件、文档输入）+ 绘图 + 打标，
三者都能各自开一个 OpenAI 兼容 API。所有推理都在设备本地完成——除了可选的 App 内 LoRA
下载，任何功能都不需要联网。无遥测，数据留在你手机上。

**这是测试版。** 它与正式版并存（包名 `com.litertchat.app.beta`），两者互不覆盖，正式版
不受影响。内容包含 2.0.4 的全部更新，另加三项只有这条分支才有的东西。

### 来自 2.0.4

- **对话的系统提示词**：对话页齿轮按钮打开底部抽屉，**按对话各存一份**。保存后对当前对话
  立即生效，不用重新开对话，历史照常保留。「清空」改成保存空输入框，独立按钮已去掉
- **修复**：对话中途改提示词不生效。提示词当时被塞进对话历史而不是系统指令，所以
  「你是猫」聊了几轮之后改成「你是狗」，模型还在演猫
- **绘图诊断**：引擎对 LoRA 的每个判断都通过一个日志回调发出，而 App 从来没注册过，
  全部信息都丢了。现在这些行——包括应用到的张量数和「跳过不兼容的 LoRA 张量」提示——
  会进 DRAW 日志，并跟着诊断报告一起走

### PixArt 现在能加载了

issue #3 报的「放进去什么也生成不出来，或者加载失败」，三种导入方式都一样。

sd.cpp 本来就支持 PixArt，问题出在命名上，而且是两处同时出问题。diffusers 直接导出的
transformer **没有任何前缀**——`PixArt-Sigma-XL-2-256x256` 里 603 个张量长这样：
`pos_embed.proj.weight`、`transformer_blocks.0.attn1.to_q.weight`——而所有探测分支都要求
`model.diffusion_model.*`，于是这个文件被当成了别的架构。同时，PixArt 的名字转换器虽然把
diffusers 的名字改对了，却依赖后面一张通用映射表补前缀，而那张表只认 `transformer.` /
`unet.` / `diffusion_model.`，裸名永远匹配不上，改好的名字缺了前缀，模型的查找全部落空。

两处都修了，并且 PixArt 现在有独立家族，不再藏在「其他」里，导入时会明确要求它真正需要的
三个文件：扩散模型、T5-XXL、VAE。它**完全不用 CLIP**——`caption_channels` 4096 就是
T5-XXL 的 hidden size。

VAE 请用 **SDXL VAE**。Sigma 的权重里没有 `csize_embedder`，所以保持 0.13025 的缩放因子，
用 SD1.5 的 VAE 会偏色。

### MOSS-Image 现在能加载了

同一类原因。Comfy 把扩散模型放在 `diffusion_models/` 下，张量是裸名——379 个，长这样：
`video_embedder.weight`、`layers.0.proj.ffn_down.weight`——而探测分支要的是带前缀的名字，
自然找不到。这就是「Moss 模型加载不了」。

MOSS 不需要新的名字映射：Comfy 的键名和模型内部名逐字一致，只差前缀。需要 Qwen3.5
文本编码器和 Flux2 VAE。

### 参考图

这是 issue #4 要的，而且它解锁的不只是 Krea2。

`ref_images` 和图生图那张起始图**不是一回事**，只有前者才是 style reference LoRA 需要的：
它作为独立 token 交给 DiT，可以给多张，怎么处理由模型决定。App 之前完全没有参考图这个概念
——JNI 没有，界面也没有——所以 style reference LoRA 能加载，但什么都不会发生。

- 绘图页多了一张参考图卡片：最多两张，点缩略图可移除
- **只在当前模型接受参考图时才显示。** 这个能力是问 sd.cpp 的，不按家族名猜——因为 FLUX 只有
  Kontext 变体接受参考图，而把参考图交给不认识它的模型不是无害的，它会改变模型预期的图结构
- 换到不支持参考图的模型会清空已选，不会留着下次误发

除了 Krea2 的 `krea2_turbo_style_reference` LoRA，这也让 FLUX Kontext、Qwen-Image-Edit、
Fibo 2、Longcat、MageFlow 变得可用，它们之前全都用不了。

### 报告问题前请看

**以上内容全部没有经过真机测试。** 名字转换是拿真实权重文件验证的——PixArt 603 个张量、
MOSS 379 个，每个键都映射到位，没有遗漏，没有冲突——但没有从这两个模型生成过任何一张图，
参考图那条路也从未跑过真实模型。如果哪里失败，这是预期之内的信息，不是意外。
