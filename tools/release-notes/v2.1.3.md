Ponko is an offline-capable AI app for Android: chat (image, file and document input) +
drawing + tagging, each of which can be served over its own OpenAI-compatible API.
All inference runs on-device: apart from the optional in-app LoRA download, no feature
needs the network. No telemetry; your data stays on your phone.
See the [README](https://github.com/visitor257/Ponko#readme).

Installs over 2.1.2. Models, settings and LoRA selections carry across.

## What's new

### Flow shift is adjustable

Requested in issue #4. sd.cpp gives every flow-matching model family a default timestep shift -
FLUX.3 Image Klein 6.93, MOSS-Image 5.0, Fibo 2.0 3.0, Krea 2 1.15, Ideogram 4 and FLUX.2 Klein
1.0 - and we never passed the parameter, so those defaults were the only values reachable. When
a default does not suit the resolution being rendered there was nothing to turn.

Both parameter cards now have a **Shift** field. Empty means use the model's own default;
filling it overrides. The value is recorded in the draw log either way, so a run can be told
apart from one where it was left alone.

One thing to know: this only affects flow-matching models. SD1.5, SDXL, PixArt and other
epsilon-prediction models route through a different denoiser that never reads the value, so the
field is a no-op for them. That is why it is not hidden per model - deciding which families are
flow-based would be a second list to keep in sync with sd.cpp.

### Fixed: diagnostic reports were losing the render log

Reported logs were missing `render start`, the parameter lines, every step and the result, while
keeping hundreds of `unused lora tensor` warnings. The cause was the 6000-character tail window
plus sd.cpp emitting one warning per mismatched tensor - several hundred of them, within five
milliseconds, all at the end of the file. They filled the window.

Runs of three or more lines sharing a signature are now collapsed before truncating. The
signature ignores the timestamp, anything inside `|...|`, and the trailing `--- file:line`, so
warnings collapse while `step 3/20` and `step 4/20` stay distinct. No keyword list to maintain.

### Fixed: a loaded model could be leaked

`sdHandle` is per-Activity but the native context lives as long as the process. When Android
destroys and recreates the activity - language change, font scale, recovery after memory
pressure - the new page starts with no handle while the context is still alive, and nothing owns
it any more. Tapping load then built a second copy: two model sets of memory for one model.

On rebuild the page now takes the context back if the selected model set still matches, and frees
it if not. Reclaiming means no reload after, say, a language change. When the identity cannot be
determined it is freed rather than adopted - a possibly-wrong handle would crash mid-render,
which is worse than a reload.

## Known limits

Unchanged from 2.1.0. The two configurations still untested are PixArt Alpha (the 512 variant)
and MOSS-Image at its recommended CFG.

## 中文说明

Ponko 是一个可离线运行的 Android AI 应用：对话（支持图片、文件、文档输入）+ 绘图 + 打标，
三者都能各自开一个 OpenAI 兼容 API。所有推理都在设备本地完成——除了可选的 App 内 LoRA
下载，任何功能都不需要联网。无遥测，数据留在你手机上。

可直接覆盖 2.1.2 安装。模型、设置和 LoRA 选择都会保留。

### 新增：可调 flow shift

来自 [#4](https://github.com/visitor257/Ponko/issues/4) 的请求。sd.cpp 给每个 flow-matching
模型族都配了默认的时间步偏移——FLUX.3 Image Klein 6.93、MOSS-Image 5.0、Fibo 2.0 3.0、
Krea 2 1.15、Ideogram 4 与 FLUX.2 Klein 1.0——而我们从来没传过这个参数，所以那些默认值就是
唯一能用的值。默认值不适合当前分辨率时，没有任何可调的地方。

两个参数卡现在都有 **Shift** 输入框。留空 = 用模型自带的默认值，填了才覆盖。两种情况都会
写进绘图日志，所以事后能分清某一次到底有没有动过它。

有一点要说清楚：它只影响 flow 系模型。SD1.5、SDXL、PixArt 以及其它 EPS 预测的模型走的是另一个
denoiser，根本不读这个值，对它们填了也没用。之所以不按模型隐藏这个框，是因为「哪些族是 flow」
会变成一份需要跟 sd.cpp 保持同步的清单，两边不一致的代价比留一个空操作更大。

### 修复：诊断报告会丢掉出图日志

用户反馈的报告里，`render start`、参数行、每一步进度和结果全都不见了，只剩几百条
`unused lora tensor` 警告。原因是每份日志只留 6000 字符的尾部，而 sd.cpp 对每个对不上的张量
各打一行警告——几百行、5 毫秒内打完、全在文件末尾，正好把这 6000 字符占满。

现在截尾前会先折叠「连续三行以上签名相同」的行。签名忽略时间戳、`|...|` 里的内容和结尾的
`--- file:line`，所以警告会折叠而 `step 3/20`、`step 4/20` 仍然各自保留。不用维护关键字表。

### 修复：已加载的模型可能泄漏

`sdHandle` 是 Activity 的字段，而 native context 与进程同寿命。Android 销毁重建 Activity 时
（换语言、改字体、内存紧张后恢复），新建的页面拿不到句柄，而 context 还活着——此时没有任何
对象拥有它。再点「加载」就会建第二份：一个模型占两份内存。

现在重建时若选中的模型集仍匹配，就把 context 接回来（所以换语言之后不用重新加载）；不匹配则
释放。判断不出身份时一律释放——拿一个可能不对的句柄出图会崩，那比重加载更糟。

### 已知限制

与 2.1.0 相同。仍未验证的两项是 PixArt Alpha（512 变体）和 MOSS-Image 在其推荐 CFG 下的表现。
