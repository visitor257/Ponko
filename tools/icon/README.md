# 图标生成

- `source.png` —— 图标原图（1920×1920，白底立绘）
- `make-icon.py` —— **抠底版**：抠掉白底、加深蓝渐变背景、边缘渐隐
- `make-icon-plain.py` —— **原样版**（当前在用）：不抠底、不换背景，原图等比缩小后居中
- `visible_sign.py` —— 可见署名模块，两个脚本共用

当前 `app/src/main/res` 里的图标由 `make-icon-plain.py` 生成。

## 用法

```bash
pip install pillow numpy
python make-icon-plain.py       # 直接写进 app/src/main/res/
python make-icon.py             # 输出到 out/res/，需手动覆盖
```

`make-icon-plain.py` 会**直接改写** `app/src/main/res/mipmap-*/` 下的文件，
不需要再手动复制。

## 可见署名（2026-10-22 起）

署名有两条路径，文案不一样，都是对的：

| 路径 | 谁调用 | 图标文案 |
|---|---|---|
| 自动 | `make-icon-plain.py`（`SIGN=1`，默认） | ≤ 72px 只画 `©`；> 72px 写 `© Ponko` |
| 手动 | `stamp_gui.py`（`SIGN=0` 出干净底图，人点位置） | 默认 `© Ponko · visitor257`，`T` 可换 |

（`make-icon-plain.py` 只画 `©` 的原因是"自动摆放要同时满足在圆内 + 不压主体"，
只剩窄窄一条弧能用；手动点的时候位置由人定，宽度就不是硬约束了。）

除背景层外，每张图标底部居中都有署名：

| 图标尺寸 | 署名内容 | 说明 |
|---|---|---|
| ≤ 72px | `©` | 只一个字符。这个尺寸上写全名每个字只有 3~4px 宽，渲染出来是一团糊 |
| > 72px | `© Ponko` | |

立绘 `app/src/main/res/drawable-nodpi/about_portrait.png` 用 `© Ponko · visitor257`，
见文件末尾的处理命令。

### 手动盖章（`stamp_gui.py`）

位置参数我调了三版都没对（见下节），而"看起来在不在角上"这件事代码里验不出来。
所以有了这个工具：**窗口里鼠标点到哪，署名就印在哪**，一屏一张。

```bash
# 双击 tools/icon/run-stamp-gui.bat，或：
python tools/icon/stamp_gui.py
```

启动时先做两件事：`SIGN=0` 重跑 `make-icon-plain.py` 得到**没有署名**的干净底图；
从 `_backup/about_portrait-original.png` 重做立绘（立绘水印不可逆，只能重嵌，不能叠）。

| 操作 | 效果 |
|---|---|
| 左键 | 在该处盖章（点击点 = 字心），然后自动进下一张 |
| `T` | 换文案：自动（按图）→ `© Ponko · visitor257` → `© Ponko` → `Ponko` → `©` |
| `+` `-` | 字号（图标和立绘分开记，改图标不影响立绘） |
| `[` `]` | 描边 |
| `C` | 显示/隐藏可见圆（红色 = 启动器不会显示的区域） |
| `Z` | 撤销上一张，回去重点 |
| `S` | 跳过 |
| `Esc` | 保存退出 |

**默认字号：占画布 0.038（图标）/ 0.024（立绘）。** 全名在 192px 图标上字宽 ≈ 34%，
立绘上 22%。之前的 0.055 是 52% —— 半个图标都在写字，太抢，已改小。

**所有 11 张用同一个文案**（不再对小图自动换成 `©`）。之前 `≤72px` 自动降级成 `©`，
用户看到的是"只有一个 c，后面没有名字"—— 那是我的判断，不是需求。现在统一全名。

**但也别指望 mdpi/hdpi 能看清**：48px 上 18 个字符均分下来字号只有 1.8px
（hdpi 2.7px）。这是物理下限，不是参数没调好。状态栏会直接标出 `字号≈1.8px`，
低于 4px 时加一行警示。那两档按 `T` 换成 `© Ponko` 或 `©` 更合适。

**鼠标旁的预览是"真实像素放大"**：用 PIL 按 `font_px()` 和同样的描边画一遍，
再 NEAREST 放大 `zoom` 倍。所以预览里的锯齿、糊，就是印出来的样子。
（早前用 Tk 的 `font=("Segoe UI", -px)` 画预览，`-px` 是 em 而不是墨迹高度，
两边比值不同 → 预览和实际大小对不上，小图上尤其离谱。）

**预览字变红 = 这个位置放不下，会被裁。** 判据是文字墨迹的**四个角**都在可见圆内，
不是只看点击的那一个点 —— "字心在圆内、两头探出去"才是最常见的半截字。

`NO_PREPARE=1` 跳过底图重置（想保留已印的、只改字号重开时用）。

**别指望把全名塞进图标右下角**：实测 0.038 字号下全名（字宽 34%n）放在
显示区 (0.74, 0.84) 仍超出圆 9~32px —— 圆形遮罩在 45° 方向只剩很窄一段弦。
全名放**底部居中**（字心 x=0.50、y≈0.83）在全部 10 张图标上都放得下。
角落能放下的只有 `©`（字宽 6~10%n）。

立绘是例外：关于页里整张显示、没有启动器遮罩，角落随便用（判据是画布边界，不是圆）。

### 位置：右下角（改过两版才对）

**第一版"底部居中"、第二版"底部右对齐"都还是偏中**，第三版才对。两次都错在同一个地方：
只看了右边界的位置，没看**文字本身的中心**。

- 第一版 `anchor="mb"`（水平居中）→ 中心就在 0.50，纯居中
- 第二版 `anchor="rb"` + 右边界 0.70 → 但 `© Ponko` 宽 0.21n，
  左边界回到 0.49n，**中心仍在 0.60**，视觉上还是偏中

现在两条约束一起满足：

| 约束 | 值 | 为什么 |
|---|---|---|
| 位置参数 | 显示区 **0.80** | 见下 |
| 文案 | 图标只用 `©` | `© Ponko` 宽 0.21n，右边界顶到 0.80 时中心只有 0.70；`©` 宽 0.06n，中心能到 0.77~0.79 |
| 判定 | **中心** ≥ 0.72 | 只看右边界会漏掉"文字很宽"这种情况 |

**位置为什么是 0.80 而不是贴边**：图标的可见区是**内切圆**，右下角是一段弧。

- 自适应前景层：只显示中间 72/108，圆半径 `n/3` → 45° 上限画布 **0.7356**
- 传统图标：整图显示，但启动器普遍套**内切圆**，半径 `0.5n` → 45° 上限画布 **0.8536**

两者换算回各自的**显示区坐标**都是 **0.8535**。所以同一个参数能用两层，
这是实测出来的巧合。取 0.80 留余量给描边和整数取整（0.83 时 48px 那档
的角正好压在圆上，浮点差一点就判超）。

`make-icon-plain.py` 跑完自检两件事，任一不过就 `SystemExit(1)`：
**① 在可见圆内**（否则被裁成半截字）、**② 墨迹中心在显示区 ≥ 0.72**（否则依然算"在中间"）。

立绘是方形图、没有启动器遮罩，用 `0.96` 真正贴角，中心落在 (0.83, 0.95)。

### 为什么是白字 + 深描边

图标底是纯白，白字只能靠描边显出轮廓；立绘底部实测平均亮度 79（偏深），
白字本身够亮。一组参数要在两头都对，所以描边宽度取字号的 7%。

描边宽度按**字号**算，不按画布 —— 按画布算的话 1024px 的图上会得到 9px 描边，
而字才 46px 高，描边比笔画还粗。

### 为什么背景层不加

自适应图标是 background 垫底、foreground 盖在上面，foreground 只在立绘处不透明。
署名画在背景层会被立绘遮掉大半，只在边缘露出残字。所以署名必须画在**前景层**。

### 为什么不做像素级不可见水印

试过，做不成：这套 DCT 水印需要 128 位，48px 图标只有 20 位容量；纯白背景层的
DCT 系数全为 0，扰动被 clip 到 255 直接丢失。而且"先给原图嵌再缩放"会让所有尺寸
全部失效（缩放打散 8×8 块）。

只给部分资源加等于给人"已经保护了"的错觉，比不加更糟。
**立绘仍是不可见水印 + 可见署名双份**（`tools/watermark.py`），图标只有可见署名。

## 三种图标的关系（提取出来是方还是圆）

**资源里没有任何圆形文件，全是方形 PNG。** 圆形是启动器/系统在运行时裁的。

| 文件 | 形态 | 谁裁 |
|---|---|---|
| `ic_launcher.png` | 方形、不透明（白底填满） | 启动器套内切圆/圆角方/方形 —— 各启动器不同 |
| `ic_launcher_round.png` | **圆形内容**，圆外透明 | 系统不裁，直接显示（`android:roundIcon` 的约定就是"资源本身是圆的"） |
| `ic_launcher_foreground.png` | 方形、四周透明（中间 72/108 是内容） | 系统合成后按遮罩裁 |
| `ic_launcher_background.png` | 方形、纯白不透明 | 同上 |

从 APK 里 `unzip` 提取：拿到的是**正方形 PNG**，圆的那个也是"方形画布 + 圆外透明"。
在手机上看着是圆，是因为启动器裁的，图本身没被裁。

所以 `stamp_gui` 窗口里那个圆是**预览遮罩**（红 = 启动器不会显示），不写进任何文件。

### round 图曾经是方图（2026-10-22 修）

`make-icon-plain.py` 里 `ic_launcher.png` 和 `ic_launcher_round.png` 都 `save(full, ...)`，
两张逐像素相同 —— 等于 round 图是方的，在"圆形图标"模式下会显示成方块。
现在 round 走 `circle()` 裁成内切圆（圆外透明）。

⚠ 用 `stamp_gui.py` 盖章时，round 是从方图**重新裁圆**派生的（`inscribe_circle`），
不是 `copy2`。同理撤销时也要重新裁。

## 可调参数

`make-icon-plain.py` 顶部：

| 参数 | 默认 | 说明 |
|---|---|---|
| `FILL` | 0.75 | 内容占画布比例。**注意**：0.75 会让约 37% 的非白像素落在可见圆外被裁掉；脚本 docstring 里写的"零裁切 ≈ 0.471"才是完全不裁的值 |
| `BG` | 纯白 | 画布底色 |
| `VISIBLE` | 72/108 | 可见区直径比例 |

`visible_sign.py` 顶部：

| 参数 | 默认 | 说明 |
|---|---|---|
| `TEXT_TINY` / `TEXT_ICON` / `TEXT_LARGE` | `©` / `© Ponko` / `© Ponko · visitor257` | 三种署名文案 |
| `MIN_WIDTH_FOR_TEXT` | 72 | 超过这个宽度才写字，否则只画 `©` |
| `TINY_SCALE` | 1.6 | 小图只画 `©` 时可以把字号放大，宽度不是约束 |
| `STROKE_RATIO` | 0.07 | 描边宽度 / 字号 |

图标实际调用的是 `make-icon-plain.py` 里的 `SIGN_KW`：

| 参数 | 值 | 说明 |
|---|---|---|
| `height_ratio` | 0.055 | 字号占画布高度。图标只写一个 `©`，可以比多字符时大 |
| `SIGN_TEXT` | `©` | 图标不含 "Ponko" 字样，原因见上表 |

`right_ratio` / `bottom_ratio` 不传给 `sign_visible`，让它走默认的 `display_room()`
（= 0.80 显示区坐标）。传了要自己保证不超圆。

立绘用 `height_ratio=0.028 / right_ratio=0.96 / bottom_ratio=0.96`，文案 `© Ponko · visitor257`。

## 局部重建（修复单张而不动其他）

```bash
# 只重建 xxxhdpi 的前景层（不动已经手工盖好章的方图）
SIGN=0 ONLY_DENS=xxxhdpi ONLY_FILES=foreground python make-icon-plain.py

# 直接从第 2 张（0 起）开始，且不重置底图
NO_PREPARE=1 START=1 python tools/icon/stamp_gui.py
```

`ONLY_FILES` 可选 `launcher`（方图+圆图）/ `background` / `foreground`，逗号分隔。

## 立绘加署名的命令

立绘不是由上面的脚本生成的，要单独处理。**注意不要用 `watermark.py --from` 重跑**
（水印不可逆，重嵌会叠加劣化），而是读现有的（已带水印的）文件，画上署名再存：

```python
import sys; sys.path.insert(0, "tools/icon"); sys.path.insert(0, "tools")
from PIL import Image
import visible_sign as vs, watermark as wm

p = "app/src/main/res/drawable-nodpi/about_portrait.png"
vs.sign_visible(Image.open(p).convert("RGBA"), vs.TEXT_LARGE,
                height_ratio=0.028, right_ratio=0.96, bottom_ratio=0.96,
                fill=(255,255,255,235), stroke=(18,20,26,225)
                ).convert("RGB").save(p, "PNG", optimize=True)
print(wm.read_mark(p))   # 必须是 100%，否则水印被破坏了
```
